# Galaxy Atelier Feature Inventory

This inventory records the user-facing capabilities and operational boundaries verified in the current repository. It is the source list for deciding what belongs in the product README; it is not intended to turn every implementation detail into marketing copy.

## Product Summary

Galaxy Atelier is a self-hosted, administrator-managed web workspace for conversational image generation and image-guided editing. It connects a prompt model and an image-generation API chosen by the operator. The application does not provide models, API credits, public account registration, or computer-control tools.

## Product Boundaries and Constraints

- The prompt model is used for prompt preparation; the host application owns authentication, sessions, persistence, provider calls, and image delivery. No shell, filesystem, browser, plugin, or arbitrary URL-fetching tools are exposed to the model. The host can include an attached image as multimodal input to the prompt provider; that provider must support the submitted format. For follow-up context, it reuses the latest successful turn that used prompt refinement, not necessarily the latest image if a later direct-to-image request succeeded.
- Self-hosting keeps application data on the operator's server, but a generation request can send its text, applicable session context, and reference image to the configured provider APIs. README wording must not imply that data never leaves the server.
- The application is built for one Node.js service process, local SQLite, and filesystem image storage. It does not currently ship horizontal scaling or object-storage support.
- Provider compatibility is contract-based, not universal. The image API currently expects base64 PNG output in `data[0].b64_json`; remote image URLs are not fetched.
- Reported cost is an estimate based on administrator-configured prices and provider usage fields. Providers may not return complete usage data.
- The UI has generation-step summaries, prompts, provider revisions, and returned model feedback. It does not display hidden chain-of-thought or a full serialized provider request.
- A listed model is not guaranteed to implement the endpoints, image-edit behavior, payload fields, and output format required by this application.

## README Editorial Decisions

### Editorial Priorities

| Priority | Topics | Reason |
| --- | --- | --- |
| **Explain in detail** | Conversational creation; optional prompt refinement; edit versus reference mode; attached and follow-up image context; generated results and visible model feedback. | These define the creative workflow and distinguish the product from a generic image API form. |
| **Summarize as supporting value** | Provider setup and model discovery; administrator-managed accounts; queues and session organization; account usage and traffic analytics; audit export; localization and themes. | These capabilities help operators and repeat users, but should not interrupt the main creative story. |
| **Keep in setup, boundaries, or omit from the product narrative** | API route lists, database fields, migration details, every chart metric, exact queue limits, image normalization internals, theme implementation, test fixtures, systemd hardening directives, and provider fallback internals. | Useful for maintainers or operators in context, but too implementation-heavy for the product introduction. Preserve only operational caveats needed for safe setup and accurate expectations. |

### Lead With

1. Conversational image creation with an optional prompt model.
2. Image editing and reference workflows, including careful follow-up context behavior.
3. Visible model feedback, named image results, and in-session preview/download/edit actions.
4. Configurable prompt and image providers with model discovery.
5. Account-scoped workspaces for administrator-managed small teams.

### Explain as Supporting Capabilities

- Persistent per-session generation queues.
- Session search, rename, archive, restore, and deletion.
- Member usage reporting and administrator traffic/account/model analytics.
- CSV audit-log export and filtering.
- English/Chinese localization and themes.
- Security and data boundaries, provider compatibility, Ubuntu deployment, backups, and development checks.

### Keep Out of the Main Product Story

- Exhaustive API routes, SQLite schema, migration history, and individual response fields.
- Every metric and chart bucket calculation.
- Detailed CSS/theme implementation, iconography, animation, keyboard shortcuts, and layout breakpoints.
- Provider fallback implementation details; retain only the relevant compatibility note in the configuration reference.
- Test fixtures, internal helper behavior, environment-variable inventories, and service hardening directives.
- Claims of hidden reasoning visibility, arbitrary API request-body inspection, universal API compatibility, or provider-free/private-by-default generation.
